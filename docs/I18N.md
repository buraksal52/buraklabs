# Localization (English / Turkish)

## Routes
English without prefix: `/`, `/projects`, `/research`, `/writing`, `/about`, `/cv`, `/contact`; Turkish at `/tr/`, `/tr/projects`, etc. Use Astro i18n config (validate against installed version). Content slug may differ by locale. Generate alternate routes via `translationKey` mapping.

## Dictionaries vs prose
Shared UI strings in typed `src/i18n/en.ts` and `tr.ts`; prose in locale-tagged MDX. Never translate code identifiers, URLs, brand names, DOI or citations automatically. Prefer culturally natural rather than literal language.

## Missing translation behavior
No synthetic page. Language switch links to translated counterpart when it exists; otherwise clear fallback to language index and optional notice. Draft translations stay hidden. No redirect by IP; manual preference may be remembered in storage but should not unexpectedly hijack deep links.

## HTML and SEO
`html lang`, locale-specific title/description, canonical per unique page, hreflang pair only if translation exists, `x-default` on main index as appropriate. Sitemap omits drafts and absent translations. Localized image alt text/captions.

## Quality gates
Run route matrix for EN/TR; no missing keys, no mixed-locale navigation, no broken internal links, no overlong label clipping, Pagefind correct language index, CV per language verified. Test query-param filters across language switch and back navigation.
