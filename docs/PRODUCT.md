# Product specification — BurakLabs

## Purpose
An independent **engineering × research × creative studio** centered on Burak's actual work. Serves recruiters, research collaborators, potential freelance clients, technical peers, and readers; avoids misleading agency/company claims. Emphasize what was built, why, evidence, contributions and repeatable techniques.

## User journeys
- **Recruiter (30–90s):** landing → selected project → role/results → CV/contact.
- **Researcher:** research index/status → method/evidence/paper → contact.
- **Developer:** project case study → architecture/demo/repo → technical writing.
- **Client:** selected work → capabilities/constraints → contact.

## MVP (ten required capabilities)
1. Filterable projects (category/tech/status/year); 2. per-project case studies; 3. transparent research statuses; 4. MDX writing; 5. web + PDF CV; 6. native/embedded/external interactive demos; 7. English + Turkish UI/content paths; 8. periodically refreshed GitHub repo metadata; 9. light/dark/system themes; 10. sitewide Pagefind search.

## Navigation and routes
English: `/`, `/projects`, `/projects/[slug]`, `/research`, `/research/[slug]`, `/writing`, `/writing/[slug]`, `/about`, `/cv`, `/contact`. Turkish: prefix `/tr/`. Translation-missing content is never faked. English is canonical default route, not forced by geo-IP.

## Home narrative
Hero studio statement + purposeful experimental scene → selected work (3–4) → research highlights → one lightweight interactive showcase → writing → personal introduction/contact. Mixed editorial layouts, not endlessly repeated cards.

## First content candidates (verify with owner before publishing)
LucidUI, Remotion Studio, Physim, AB/C, Ghostellar, MIV Blockspace. These names are candidate entries, NOT permission to claim outcomes or public availability. Paper/acceptance statuses and CV must be owner verified. Research topics only after their existence and publication rights are confirmed.

## Explicitly out of scope
Accounts, comments, admin panel, runtime DB, AI chat, full realtime GitHub firehose, shared backend, auto-generated CV claims, CMS UI, all products embedded in parent page. Contact can be mailto + verified profiles; no form backend.

## Success conditions
Real portfolio content, two working demos (can be small native simulators), complete UI translations + honest missing-content handling, reliable navigation/search, accessible reduced-motion experience, verified data/links, clear route to PDF CV and contact. Avoid artificial traffic/conversion claims.
